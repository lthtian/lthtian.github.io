WinDbg 学习记录

程序故障的排查入口

入口 典型情况
执行过程中发生异常 非法访问、整数除零、非法指令、栈溢出。
程序或运行库决定终止 未捕获 C++ 异常、terminate、abort、Fail-fast。
资源耗尽 提交额度、虚拟地址空间等不足，分配失败后程序无法继续；不一定是物理 RAM 用完。
依赖与集成问题 DLL 缺失、位数或版本不匹配、接口不一致；可能表现为启动失败或运行中崩溃。
第三方模块注入 输入法、安全软件等模块进入进程，引发同名 DLL 冲突、依赖加载失败或运行中崩溃。
系统、驱动与硬件问题 系统软件缺陷，或 CPU、内存、存储等异常；可能影响应用，也可能导致系统蓝屏。
需要另行区分的事件 卡死、外部结束进程、掉电重启；这些不能全部算作应用崩溃。

转储

系统崩溃转储

Windows 蓝屏时，按“启动和故障恢复”中的有效配置自动保存系统现场。小内存转储默认位于 C:\Windows\Minidump\，核心、完全、自动和活动内存转储默认位于 C:\Windows\MEMORY.DMP；路径可配置。

普通进程转储与 ProcDump

保存指定进程的线程、寄存器、模块和选定的内存等状态，可通过 WER、ProcDump 或程序自身的采集机制生成。崩溃、卡死或正常运行时均可采集；DMP 是采集时刻的快照，不包含完整执行历史。

使用 ProcDump 前先解压工具、创建输出目录，在工具所在目录的 CMD 中执行。以下进程名和 PID 按实际情况替换。

条件触发采集：保持 ProcDump 运行，遇到未处理异常时保存；目标尚未启动时等待它启动。

即时采集：立即保存 PID 为 1234 的进程当前状态，无需等待异常。

-ma：进程完整转储；-e：监视未处理异常；-w：目标未启动时等待。崩溃转储应在进程完全退出前采集，可提前配置自动触发。

内存分类与转储范围

内存可从不同维度理解：

  • 物理与虚拟：物理内存是整机 RAM；进程虚拟内存是该进程的地址与映射，不等于实际占用的 RAM。多个进程可映射同一物理页。
  • 用户态与内核：用户态内存包括应用代码、堆、用户栈；内核内存包括系统内核、驱动及进程／线程管理数据等，并非某个系统进程的用户态内存。
  • 驻留状态：驻留页当前位于 RAM；合法的未驻留页可在访问时调入或按需获得物理页。
转储类型 保存范围
系统小内存转储 蓝屏代码、关键上下文、故障线程的内核栈、驱动列表等基本信息。
系统核心／自动内存转储 系统范围的内核和内核驱动内存，通常不包含应用的用户态内存。
系统完全内存转储 Windows 使用的物理内存，包括当时驻留的各进程用户态内存；不等于所有进程的全部虚拟内存。
系统活动内存转储 类似完全转储，但过滤部分不太可能与分析有关的页面。
ProcDump 默认 Mini（-mm） 线程栈及其直接、间接引用的内存，以及线程、模块、句柄等元数据；不保证保存完整堆。
ProcDump -ma 目标进程可读取的用户态虚拟内存及元数据，包括堆、栈、映像和映射内存；不包含系统内核内存。

DMP 中读不到某地址，可能是该内存未被采集，不能直接认定原进程中的地址无效。

PDB 核心概念

PDB（Program Database）是与 EXE／DLL 配套的调试信息数据库，通常保存函数名与代码位置、源码行映射、类型和成员布局，以及可用的参数、局部变量位置描述。VS、WinDbg 用这些信息将机器代码和内存关联到 C++ 代码。

DMP 保存某次运行的现场，PDB 提供定位和解释信息，不记录该次运行的变量值，通常也不包含完整源码。例如，没有 PDB 时，调用栈中的位置可能显示为 MyApp+0x1234；加载匹配的 PDB 后，可以进一步识别为 MyApp!Worker::Run+0x4，并在具备行号信息时对应到源码行。

没有 PDB，仍可查看 DMP 中保存的异常、寄存器和原始内存；具备相应机器码时可查看汇编，栈与展开信息充分时也可恢复调用栈。主要缺少内部函数名、源码行和类型等解释信息，难以直接按名称查看变量；部分函数名仍可来自模块导出表。即使有 PDB，优化、符号裁剪或 DMP 缺少内存，也可能限制变量查看。

Debug、Release 均可生成 PDB；是否生成调试信息与是否进行优化是不同设置，程序正常运行通常不依赖 PDB。分析时，PDB 必须匹配实际运行的 EXE／DLL 构建；文件同名或使用相同源码重新构建，不保证匹配。源码不能直接替代二进制文件或配套 PDB。

符号、符号源与加载

符号信息保留程序中的名称、代码位置、类型布局和源码行等对应关系，PDB 是其主要载体。公有符号主要提供函数、全局符号的名称与位置；私有调试信息还可包含局部变量、类型和行号。完整 PDB 通常包含二者，模块导出表也能提供部分名称。

WinDbg 按模块分别寻找匹配的 PDB，现代 MSVC PDB 通常通过 GUID＋Age 校验具体构建。结合模块加载基址和符号信息，可以将现场地址解释为“模块!函数＋偏移”，并在信息充分时关联到源码行。符号帮助解释现场，根因仍需结合 DMP 分析。

符号源是获取符号文件的位置，可以是本地目录、共享目录或网络服务器。符号仓库按文件名和构建标识组织多版本文件；微软源主要提供微软组件，自建源可维护业务模块。配置了来源，不代表其中一定存在所需文件。

加载符号是读取 PDB，供当前 WinDbg 会话查询；下载是从远端取得文件。WinDbg 默认按需加载，匹配的本地缓存可复用，无需每次重新下载。分析小型 DMP 时，还可能获取匹配的 EXE／DLL／SYS 等二进制映像。

服务器正常回复“文件不存在”（如 HTTP 404）通常较快；连接或响应迟缓、重试、代理查询上游，以及多个来源和文件的查找，都可能增加等待时间。**Downloading 不保证正在传输数据或最终获取成功**；未取得文件时，后续会话仍可能重复查找。

路径检查中的 Deferred 表示检查被推迟，**OK** 表示路径通过检查，都不能证明已加载匹配 PDB。lmvm 模块名 可查看模块符号状态，**(no symbols)** 表示未加载调试符号；Loaded symbol image file 描述模块映像，不能证明 PDB 加载成功。!sym noisy 开启详细符号查找日志，!sym quiet 关闭，可用于区分本地命中、远程查找和请求失败。

配置方式与会话命令

预先配置：在 WinDbg 的 File → Settings → Debugging settings 中设置路径，保存后供后续会话使用。Source path 用于查找源码，Symbol path 用于查找符号，Default cache 是默认缓存位置；某个 srv* 项明确指定缓存目录时，该项使用指定目录。初始符号路径也可来自 _NT_SYMBOL_PATH 等环境变量。

会话配置：在 Command 窗口底部输入命令，按回车执行。0:003> 等提示符不属于命令，.、! 使用英文半角字符。命令修改当前会话的配置，但路径等设置可能随 WinDbg 设置／工作区保存，不能认为命令修改一定是临时的。

命令 作用
.sympath 查看当前符号路径。
.sympath 路径 替换整个符号路径；多个搜索项用 ; 分隔。
.sympath+ D:\MyPdb 追加本地 PDB 目录；示例目录按实际位置替换。
.sympath+ srv*E:\LDSSymbols*http://114.115.237.236/symbols 追加远程符号源与本地缓存。
.srcpath 查看当前源码路径。
.srcpath D:\c_expand\client 替换源码路径；使用 .srcpath+ 可追加。
.reload /f c_expand.exe 立即尝试重新加载指定模块的符号。
lmvm c_expand 查看指定模块的信息及符号加载状态。

常用流程是 查看路径 → 设置或追加来源 → 加载指定模块的符号 → 核对结果。.sympath 本身只配置查找位置，不立即下载；加载时复用匹配的本地文件，缺少时才向配置的远程来源获取。

寄存器基础

以下为 x86 的 32 位寄存器及相关状态字段，WinDbg 默认以十六进制显示。通用寄存器可存整数、地址或临时数据，具体含义需结合指令与调用约定判断。

  • 执行位置与调用栈：
    • EIP（Extended Instruction Pointer）：指令指针，保存执行位置对应的机器指令地址。
      • 用途：定位当前模块、函数及汇编指令；匹配 PDB 具备行号信息时可关联源码，也为调用栈展开提供起始代码位置。
    • ESP（Extended Stack Pointer）：栈指针，指向当前线程栈顶；调用、压栈和出栈等操作会改变它。
      • 用途：作为读取栈内存、展开调用栈的起点；还需结合已采集的栈内存和展开规则，不能仅凭 ESP 数值还原完整调用链。
    • EBP（Extended Base Pointer）：常作为栈帧基准，用于定位参数、局部变量；优化后可能改作通用寄存器，不能始终依赖 EBP 链还原调用栈。
      • 用途：保留帧指针时，可结合保存的 EBP 和返回地址追溯调用者；结合 PDB 的位置描述，如 EBP-0x10，定位参数、局部变量并读取其值。
  • 通用寄存器：
    • EAX（Accumulator）：常用于运算和整数／指针返回值，执行中也可保存临时数据。
    • ECX（Counter）：常用于计数或临时数据；x86 __thiscall 在函数入口用它传递 this，函数内部可改写。
    • EBX（Base）、EDX（Data）、ESI（Source Index）、EDI（Destination Index）：可保存数据、指针等；某些指令对其有约定用途，不能只按名称推断当前含义。
  • x64 对应 RIP、RSP、RBP、RAX 等 64 位寄存器，调用约定也有区别。
  • 线程切换与寄存器保存：同一逻辑处理器轮流运行不同线程时，Windows 会将被切出线程所需的寄存器状态保存到内存，再恢复下一线程的状态；原线程重新运行时恢复自己的值。因此，每个线程拥有独立的寄存器状态，但不永久独占一套硬件寄存器。

WinDbg 结合 EIP、ESP 等寄存器、栈内存及展开信息还原调用链；遇到访问违规，还需检查故障指令实际使用了哪些寄存器。

Dump分析命令

命令分类

  • 无前缀：普通命令（Commands）。调试器内建，如 r、k、u、dd。
  • .：元命令（Meta-Commands）。也由调试器内建处理，常用于上下文选择、配置和辅助检查，如 .ecxr、.frame、.sympath。
  • !：扩展命令（Extension Commands）。由扩展 DLL 提供，调试器查找并调用其命令入口，如 !analyze、!address；扩展可由微软或第三方提供。
    • 可用 !库名.命令 指定扩展库，如 !ext.address 地址 中的 ext 表示 ext.dll。

异常记录与寄存器上下文

上下文是保存的一组寄存器值；异常发生时与采集 dump 时的记录可能不同。

  • .exr：查看异常记录，不切换寄存器上下文。

    • 用法：.exr -1 查看最近的异常；.exr 地址 查看指定位置的异常记录，地址不是故障指令地址。
    • ExceptionCode：异常类别，决定 Parameter[n] 的解释方式。以下异常码均为十六进制：
      • Access violation（C0000005）：访问违规。参数 [0]：0 读、1 写、8 执行；[1]：被访问的目标地址。
      • C++ EH exception（E06D7363）：MSVC C++ 异常，EH 即 Exception Handling。[0] 常见 19930520，为内部标记；[1]：异常对象地址；[2]：类型描述信息地址；x64 通常还有 [3] 映像基址。Type 为解析出的类型名，需结合抛出调用链判断原因。
      • Security check failure or stack buffer overrun（C0000409）：安全检查失败／Fail-fast。[0] 为子码，如 2 表示栈 Cookie 检查失败，不能仅凭英文说明认定栈缓冲区溢出。
      • In-page I/O error（C0000006）：页面调入失败。前两个参数同访问违规，[2] 为底层失败状态码。
      • Stack overflow（C00000FD）：栈溢出／栈无法继续增长，检查递归、栈空间及提交资源。
      • Integer divide-by-zero（C0000094）：整数除零。
      • Illegal instruction（C000001D）：非法指令。
      • Heap corruption（C0000374）：检测到堆损坏，破坏可能发生在更早的位置。
      • Break instruction exception（80000003）：断点异常，不一定是程序故障。
    • ExceptionAddress：异常发生或报告的位置。访问违规通常指向故障指令；C++ 异常可能指向 RaiseException，需沿调用栈找抛出者。
    • ExceptionFlags：0 未设置不可继续标志；1 表示不能直接从原位置恢复执行，不等于不能被 C++ catch 捕获。
    • NumberParameters：有效异常参数数量；Parameter[n] 是这些附加数据，不是业务函数的参数。

  • .ecxr：采用并显示异常时的寄存器上下文，可记作 Exception Context Record。

    • 自动读取 dump 中配套保存的异常上下文，**不需要先执行 .exr -1**；不是根据异常地址跳转代码。

  • .cxr：采用指定或默认的寄存器上下文。

    • 不带参数：在用户态 dump 中恢复当前线程的默认记录，通常是采集时的状态。
    • **.cxr 地址**：采用该地址保存的 CONTEXT 记录，地址不是代码位置。

切换后，**r 查看当前寄存器，k 查看对应调用栈**。只能切换已保存的记录，不会执行程序或恢复历史内存。

线程与调用栈

  • **~**：列出当前进程的线程；行首 . 表示当前线程，左侧数字是 WinDbg 的线程索引。
  • **~1s**：切换到索引为 1 的线程，数字按实际替换，不是 Windows 线程 ID。
  • k：查看当前选中线程的调用栈，不固定查看线程 0，也不会自动切回线程 0。

切换线程会恢复其默认寄存器上下文；要查看异常时的栈，先选中异常线程，再执行 .ecxr、k。

模块查询

模块通常对应已加载的 EXE／DLL；内核调试中也包括 SYS 驱动。

  • lm（List Loaded Modules）：查看模块列表，包括加载地址范围、模块名和符号状态；start 为基址，end 为范围结束后的第一个地址。
  • **lmf**：显示模块完整映像路径，用于检查第三方模块或非预期的 DLL 加载路径；f 为完整路径显示选项。
    • **lmf m *sogou***：筛选名称中含 sogou 的模块并显示路径；m 按模块名筛选，* 为通配符。
  • **lmvm 模块名**：查看指定模块的详细信息，重点看 Image path、File version、Timestamp 和符号状态。其中 v 表示详细显示，m 指定模块名；名称通常不带 .dll／.sys 等扩展名。

寄存器与反汇编

  • r（Registers）：查看当前上下文的常用寄存器值，不切换上下文；查看异常时的值应先执行 .ecxr。
    • **r eax：查看一个寄存器；r eip,esp,ecx**：同时查看指定的几个寄存器。
  • u（Unassemble）：将指定地址处的机器码解释为汇编指令。
    • **u @eip L8**：从 EIP 指向的位置显示 8 条指令；@eip 表示取寄存器值作为地址，x64 使用 @rip。
    • 也可直接指定地址，如 u 0x12345678 L1，地址按实际替换；L1 表示显示一条指令。
    • 指令行依次显示地址、机器码、汇编指令。反汇编只是查看，不会执行指令或改变寄存器值。

内存查看

**dd 地址 L数量**：按 DWORD（4 字节）以十六进制显示原始内存，用于核对字段、指针或数组数据，不限于栈。

  • **dd @esp L8**：从当前 ESP 指向的地址读取 8 个 DWORD，共 32 字节，不是 8 条指令。
  • **dd @esp+0x54 L1**：读取 ESP＋0x54 处的一个 DWORD；也可直接指定地址。
  • 输出左侧为每行起始地址，右侧为数据；???????? 表示无法读取，也可能只是 dump 未收录该内存。

**!address 地址**：查看该地址所在区域的属性。访问违规时，可查询 .exr -1 中 Parameter[1] 的目标地址。

  • **Usage**：用途，如 Stack 栈、Heap 堆、Image 映像。
  • **State**：MEM_FREE 空闲、MEM_RESERVE 已预留、MEM_COMMIT 已提交；提交不等于驻留或已被 dump 收录。
  • **Protect**：权限，如 PAGE_READWRITE 可读写、PAGE_READONLY 只读、PAGE_NOACCESS 不可访问。
  • **Type**：MEM_PRIVATE 私有内存、MEM_IMAGE 映像映射、MEM_MAPPED 其他映射。

地址空间与堆分析

  • **!address -summary**：查看进程虚拟地址空间统计及最大连续空闲区域；Free 不是整机剩余 RAM。
  • **!heap -s**：查看各堆的预留、提交和空闲空间，常用列单位为 KB；可增长堆的 Free 不足不代表申请必然失败。
  • **!heap -x 地址**：查找包含该地址的堆块，查看所属堆、块地址和大小；查不到不等于已经释放。
  • **!heap -p -a 地址**：查看 Page Heap 块的分配／释放状态及可用调用栈；需在程序启动前启用 Page Heap，并采集相关数据，不能给旧 dump 补历史。

卡死与 CPU 占用分析

  • !runaway：查看线程累计用户态 CPU 时间；!runaway 7 同时显示用户态、内核态 CPU 时间和线程存活时间。累计耗时不等于当前 CPU 占用率。
    • 找到高耗时线程后，用 ~索引s → k 查看采集时的调用栈，定位业务函数，结合源码检查循环、重试或大量计算。
  • !cs：查看 Windows 临界区的快照状态；OwningThread 是持有者线程 ID，**RecursionCount** 是尚未配对退出的进入次数（含首次）。
    • LOCKED 不等于死锁；结合相关线程的 k，确认等待关系是否形成闭环。
  • **!analyze -hang**：自动提供卡死／线程阻塞线索，需结合线程栈验证。

自动分析报告：!analyze -v

!analyze 是 ext.dll 提供的自动分析扩展，-v 表示详细输出。底层通过调试引擎读取已保存的现场，并结合符号和分析规则生成报告，主要包括：

  1. 读取现场：用户态崩溃读取异常记录与配套上下文；蓝屏读取 Bug Check 代码和参数，并取得相关线程、模块及可用内存信息。
  2. 解释地址与数据：按配置的符号路径查找匹配 PDB，将地址对应到模块、函数、源码行或类型；需要时还会获取匹配的二进制映像。缓存未命中、远程查找或超时都可能增加等待时间。
  3. 展开调用栈、解析故障细节：结合寄存器、栈内存及展开信息恢复调用链，按异常类型解释参数，必要时解析 C++ 异常类型等信息。
  4. 自动归因与分类：依据故障类型、现场和分析规则选择可疑模块／函数，生成摘要、Bucket 等结果；并非固定执行一串常用命令。

它分析快照，不会重新执行程序或恢复完整历史。异常、寄存器等现场数据与自动推断的可疑模块应区分看待；结论受转储范围、符号及调用栈可靠性限制。

重要字段（按排查顺序）：

  • 故障类型：发生了什么
    • EXCEPTION_CODE／EXCEPTION_RECORD：异常类别与参数；C++.Exception.Type／Type 为 C++ 异常类型，需结合抛出条件判断原因。常见异常码见下节 .exr。
    • **BUGCHECK_CODE ＋ Arguments／BUGCHECK_P1～P4**：蓝屏类别与具体条件，参数含义由停止码决定。例如 1a — MEMORY_MANAGEMENT ＋ Arg1: 41790 表示页表页损坏，不能直接认定内存条故障。
  • 执行现场与调用链：在哪个操作中出错
    • **CONTEXT：寄存器现场；FAULTING_IP／Failure.Exception.IP.***：异常发生或报告的指令位置，须与被访问的数据地址区分。
    • **FAULTING_THREAD**：相关线程；内核报告中通常是线程对象地址。
    • STACK_TEXT：调用栈，沿栈查业务操作与调用者；STACK_COMMAND 可重现该栈。异常报告／检测位置可能晚于真正出错的位置。
  • 可疑模块与函数：优先查谁
    • **MODULE_NAME：自动分析选出的重点怀疑模块；IMAGE_NAME**：对应的 EXE／DLL／SYS 文件。
    • **SYMBOL_NAME**：选中的函数或模块内位置；模块+偏移／unknown_function 表示未解析出具体函数名。
    • 用 lmvm 模块名 核对版本等信息，再结合故障指令、调用栈及触发场景验证；仅指向 nt 等系统模块时，仍需检查是否由其他模块先破坏了内存。
  • 故障分类：用于相似案例比对
    • FAILURE_BUCKET_ID／Failure.Bucket：常组合故障码、子类型、模块和函数，用于搜索、归类多个 dump。相同 Bucket 不保证根因相同，其中模块名与 MODULE_NAME 可能来自同一次归因。
    • **FAILURE_ID_HASH／Failure.Hash**：故障分类签名，不是模块文件哈希。
  • 辅助信息：按需查看
    • **PROCESS_NAME**：相关进程；蓝屏时表示进程上下文，不代表该进程导致蓝屏。
    • **IMAGE_VERSION：所选模块版本；WER.Process.Version**：进程映像版本。
    • **Analysis.***：分析工具的版本、耗时及资源统计，不能据此判断故障程序内存不足或 CPU 异常。
